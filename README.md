# ResolveDesk

**A Python support-ticket workspace with customer, agent and administrator roles.**

FastAPI · Jinja2 · SQLAlchemy · PostgreSQL · Docker · Jenkins

## Start here: Docker Compose

Install Docker Engine with the Compose plugin (or Docker Desktop) and Python 3.
Extract this ZIP, open a terminal in the `resolvedesk` folder, then run:

```bash
python setup_env.py
docker compose up -d --build
```

On Ubuntu, use `python3` instead of `python` if needed. Open **http://localhost:8000**.
On a cloud VM, use its public IP and permit TCP 8000 only from your own IP for testing.
Compose starts PostgreSQL, waits for it to be healthy, then starts the application.

Create a customer account through **Create account**. There are **no default passwords**.

### Create your administrator

```bash
docker compose exec app python -m app.manage create-admin --email admin@example.com --name "Support Admin"
```

Enter a new password at the hidden prompts. Use a different email from your customer account.
Sign in as admin, open **Team**, and promote a registered customer to **agent**.
Admin creation is explicit; public registration can never grant staff privileges.

## Try the complete workflow

1. Register a customer and submit a ticket with a title, description and priority.
2. Register another account for a support agent.
3. Bootstrap an admin with the command above, sign in, and promote the agent in Team.
4. Open the ticket as admin and assign it to the agent.
5. Sign in as the agent and change status to In Progress. Add a reply.
6. Sign in as the customer to see the reply; reply back.
7. Resolve the ticket as staff. Use search, status and priority filters to find it.
8. Restart the application (`docker compose restart app`) and verify the data remains.

Customers see only their own tickets. Agents can see and update all tickets, but only
admins can assign tickets or change roles. Admins cannot demote their own account.
The inbox displays 10 tickets per page. UTC timestamps are used throughout.

## Run without Docker (SQLite development)

Requires Python 3.11 or newer. From this directory:

```bash
python -m venv .venv
```

Activate on Ubuntu/macOS: `source .venv/bin/activate`.
Activate on Windows PowerShell: `.venv\Scripts\Activate.ps1`.

```bash
pip install -r requirements-dev.txt
```

Generate an application key and set the environment:

Ubuntu/macOS:
```bash
export SECRET_KEY=$(python -c "import secrets; print(secrets.token_hex(32))")
uvicorn app.main:app --reload
```

Windows PowerShell:
```powershell
$env:SECRET_KEY = python -c "import secrets; print(secrets.token_hex(32))"
uvicorn app.main:app --reload
```

Keep this key consistent across restarts if you want sessions to stay valid.
SQLite creates `resolvedesk.db` in the current directory. Create an admin from
another activated terminal with the same environment/key:
`python -m app.manage create-admin --email admin@example.com`.
The app does not automatically read `.env`; Compose passes it, or your shell must export it.

## Tests

```bash
python -m pytest -q
```

Tests use a disposable SQLite database and cover login, duplicate registration,
validation, CSRF protection, customer isolation, staff permissions, assignment,
comments, role management, HTML escaping, logout, pagination and health endpoints.

Docker test alternative:
```bash
docker build -f Dockerfile.test -t resolvedesk-tests .
docker run --rm resolvedesk-tests python -m pytest -q -p no:cacheprovider
```

## Architecture

The browser sends HTML forms to FastAPI. Jinja renders the pages server-side;
no Node.js build or external CDN is required. SQLAlchemy stores accounts, tickets
and comments in PostgreSQL. Signed HttpOnly session cookies contain a user ID and
CSRF token; roles are retrieved from the database on each request. Passwords are
salted and hashed with PBKDF2-HMAC-SHA256 (600,000 iterations).

## Main routes

| Route | Purpose |
|---|---|
| `/register`, `/login` | Account creation and authentication |
| `/` | Role-aware dashboard, filters and pagination |
| `/tickets/new` | Ticket creation form |
| `/tickets/{id}` | Ticket details and conversation |
| `/admin` | Administrator team management |
| `/health/live` | Process liveness |
| `/health/ready` | Database connectivity |
| `/docs` | FastAPI route documentation (forms/session authentication) |

POST routes require the hidden form token from the corresponding page. This is
a web application with documented routes, not a separate JWT REST API product.

## Configuration

| Variable | Meaning |
|---|---|
| `SECRET_KEY` | Required random signing key, at least 32 characters; same across replicas |
| `DATABASE_URL` | SQLAlchemy connection URL; defaults to local SQLite |
| `POSTGRES_PASSWORD` | Compose database password; generated by setup_env.py |
| `COOKIE_SECURE` | `false` for local HTTP; set `true` behind HTTPS |

Never commit `.env`, database files or real Kubernetes Secrets. `.gitignore`
excludes them. `setup_env.py` keeps existing values instead of rotating them.

## Jenkins CI

`Jenkinsfile` expects an agent labelled **resolvedesk-build** with Git, Docker
and access to the Docker socket. Create a Pipeline from SCM pointing at your
repository. It checks out code, builds a disposable test image, publishes JUnit
results and builds `resolvedesk:<build-number>` only after tests pass.
It intentionally does not push to an invented ECR repository or create AWS resources.

## Preparing for AWS EKS

`k8s/app.yaml` is a starter Deployment and ClusterIP Service, **not an EKS
provisioning stack**. To deploy it later:

1. Provision EKS, managed nodes, networking and a PostgreSQL database (for example RDS).
2. Build and push this image to your ECR repository using an immutable tag.
3. Replace `REPLACE_WITH_ECR_IMAGE_URI` in the manifest.
4. Create namespace `resolvedesk`, then a Secret named `resolvedesk-env` with
   `SECRET_KEY` and `DATABASE_URL` using your private credentials.
5. Apply the manifest. Configure HTTPS ingress/ALB before using the secure session cookie.
6. Bootstrap the admin using `kubectl exec -it -n resolvedesk deploy/resolvedesk -- python -m app.manage create-admin --email YOUR_EMAIL`.
7. Point Argo CD at the environment manifests and extend Jenkins with ECR push
   and GitOps image updates after AWS IAM is configured.

Database tables are created on first startup for this initial version. Start with
one replica. Before enabling concurrent first starts or modifying the schema,
introduce versioned Alembic migrations executed once per release. Existing schema
changes are not automatically migrated. PostgreSQL supports shared data across
replicas; SQLite is only for single-process development.

## Operations and limitations

```bash
docker compose logs --tail=100 app
docker compose ps
docker compose down
```

`docker compose down` retains the database volume. **`docker compose down -v`
deletes the database permanently.** Keep backups before destructive operations.

This is a working portfolio application, not a claim of production hardening.
It does not include email delivery, password reset, MFA, attachments, audit logs,
login throttling, or Terraform/EKS provisioning. Before public use, add HTTPS,
rate limiting, migration management, tested database backups and appropriate
security review. An application restart does not delete PostgreSQL data.

## Verification in the delivery environment

Application tests were run against SQLite. Docker and a PostgreSQL server were
not available in the delivery environment, so Compose container startup and
PostgreSQL integration still require verification on your machine. Dependency
versions are pinned to those used by the test environment.
